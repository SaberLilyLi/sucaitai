# 素材台：以腾讯文档为在线素材库的技术方案

**状态：** 方案讨论稿
**日期：** 2026-07-27
**适用范围：** 素材台（淘宝 / 1688 选品、素材拉取、归档与团队协作）

---

## 1. 背景与目标

当前素材台将归档商品保存到本地 `data/library.json`，腾讯文档导出功能则会在每次导出时创建一张新的在线表格。该方式适合单机演示，但不适合作为团队长期维护的素材库：数据分散、无法从在线表格反向查询，也不能可靠地避免重复上传。

本方案目标是将**腾讯文档在线表格作为用户的主素材库**：

1. 用户授权后选择或创建自己的腾讯文档空间；
2. 按项目将商品拆分到不同文件夹、不同在线表格；
3. 素材台根据 `file_id + sheet_id` 读取指定项目表；
4. 归档时以商品 ID 去重，只追加新商品或更新已有行；
5. 用户可在腾讯文档中直接查看、编辑、协作，素材台读取最新数据；
6. 不要求用户自行部署或维护业务数据库。

---

## 2. 可行性结论

### 2.1 技术上可行

素材台现有的 FastAPI + Python 架构可以承担：腾讯文档授权凭证管理、远程表格读取、筛选、去重、批量写入和短时缓存。

腾讯文档的官方能力已证明“授权后读取在线表格并选择指定 sheet”是可行的；腾讯云 BI 的接入流程支持用户按 URL 或“我的文档”选择有查看权限的在线 Excel 和指定 sheet，并以首行作为字段名称。[腾讯云 BI：腾讯文档建表](https://cloud.tencent.cn/document/product/590/79763)

腾讯文档 MCP 的官方说明也列出了空间节点查询、创建空间节点，以及表格读取/更新相关能力；其中 `create_space_node` 支持创建 `wiki_folder` 文件夹节点。[腾讯文档 MCP 官方说明](https://developer.cloud.tencent.com/mcp/server/11803)

### 2.2 当前代码尚未具备

当前 [`server/tencent_docs_client.py`](../.cursor/skills/taobao-sales-scraper/server/tencent_docs_client.py) 只实现了：

- 创建在线表格；
- 读取新表格的工作表元信息；
- 批量写入单元格。

尚未实现：

- 用户选择/绑定已有腾讯文档；
- 读取某个表格的行数据或指定范围；
- 查询和创建文件夹；
- 按商品 ID 去重；
- 固定项目表的追加/更新；
- 在线数据缓存和同步状态记录。

因此，结论是：**架构可以实现，但需要新增腾讯文档读写与空间管理适配层。**

## 3. 推荐信息架构

不要把所有商品放在一张大表中，也不要按固定行数硬拆分。建议按业务项目拆分。

```text
腾讯文档空间
└── 素材台
    ├── 选品目录表（索引）
    ├── 2026 夏季女装（文件夹）
    │   └── 商品素材库（在线表格）
    ├── 家居百货（文件夹）
    │   └── 商品素材库（在线表格）
    └── 已归档项目（文件夹）
        └── 2025 秋冬女装（在线表格）
```

### 3.1 选品目录表（索引表）

目录表本身也存放在腾讯文档中，用来保存项目与在线表格的稳定映射；它替代自建数据库中的项目表。

| 字段 | 说明 |
| --- | --- |
| `project_id` | 项目唯一 ID，系统生成 |
| `project_name` | 用户看到的项目名称 |
| `folder_id` | 腾讯文档文件夹/空间节点 ID |
| `file_id` | 项目素材表的文档 ID |
| `sheet_id` | 项目素材表的工作表 ID |
| `status` | 进行中、已归档 |
| `product_count` | 商品数量（可异步更新） |
| `created_at` | 创建时间 |
| `updated_at` | 最近同步时间 |

程序只依赖 ID，不依赖文件夹或表格名称，因为用户可能重命名文档。

### 3.2 项目素材表字段

所有项目表必须使用统一表头，第一行不得为空、不得合并单元格。

| 字段 | 用途 |
| --- | --- |
| `商品ID` | **唯一键**，用于去重和更新 |
| `标题` | 商品标题 |
| `平台` | 淘宝、1688 |
| `商品链接` | 原始商品 URL |
| `价格` | 搜索/详情页价格 |
| `销量` | 数据源提供时写入 |
| `发货地` | 商品发货地 |
| `发货时效` | 24 小时、次日达等 |
| `项目` | 与目录表项目名称保持一致 |
| `标签` | 用逗号分隔或按表格字段类型存储 |
| `备注` | 选品理由、风险和后续动作 |
| `素材状态` | 未拉取、部分完成、已完成 |
| `主图数` / `SKU图数` / `详情图数` / `视频数` | 素材完整度 |
| `素材包路径或链接` | 可选；用于关联本地/云端素材 |
| `首次归档时间` | 首次写入时间 |
| `最近同步时间` | 最近一次同步时间 |

> 腾讯云 BI 的接入说明同样建议首行作为字段名称，且提示合并单元格会导致读取异常；项目表应保持扁平、规范的表格结构。[腾讯云 BI：腾讯文档建表](https://cloud.tencent.cn/document/product/590/79763)

## 4. 核心流程

### 4.1 首次接入

```text
用户授权腾讯文档
  → 用户选择已有“素材台”目录，或系统创建目录
  → 用户选择已有目录表，或系统创建“选品目录表”
  → 校验目录表字段
  → 保存根目录与目录表 ID 到本地连接配置
```

“连接配置”只保存非业务元信息，例如当前账号的目录表 `file_id`；它可以保存在本地 `data/tencent_docs_connection.json`，不承担商品数据存储职责。

### 4.2 创建项目

```text
输入项目名称
  → 在素材台根目录下查询同名项目文件夹
  → 存在则复用，不存在则创建文件夹
  → 在项目文件夹创建在线表格
  → 写入标准表头
  → 将 project_id、folder_id、file_id、sheet_id 追加至目录表
```

### 4.3 读取和查询

```text
用户选择项目
  → 读取目录表对应行
  → 获取 file_id + sheet_id
  → 拉取该项目表数据（分页或指定范围）
  → FastAPI 在内存中执行关键词、标签、项目、状态筛选
  → 返回当前页数据和总数
```

2,000 条商品、约 15 个字段约等于 3 万个单元格；对于单项目选品表不是大数据量。应避免每次前端交互都全表请求：建议服务端设置 1–5 分钟短时缓存，并提供“刷新在线数据”按钮强制重读。

### 4.4 去重同步

```text
用户勾选商品并点击“归档到当前项目”
  → 读取项目表的“商品ID”列（优先从短时缓存读取）
  → 生成 existing_ids 集合
  → 本次商品按商品 ID 去重
  → 新商品：追加到末行
  → 已存在商品：默认跳过；可选“更新素材状态/标签/备注”
  → 返回“新增 X 条，跳过 Y 条，更新 Z 条”
```

唯一键必须使用商品 ID。商品标题、价格和 URL 都可能变化，不能作为可靠的去重依据。

### 4.5 冲突处理

多人同时写入时，可能发生“双方都未读取到对方刚写入的 ID”的竞争条件。第一阶段采用以下轻量策略：

1. 服务端对同一 `file_id` 使用进程内异步锁；
2. 写入前强制刷新一次商品 ID 列；
3. 写入后更新缓存；
4. 若发现重复，保留最早一行并在页面提示。

单台桌面应用或小团队场景足够；将来多机器并发时，再引入共享锁或专用数据库。

## 5. 后端改造范围

建议将腾讯文档逻辑从单一客户端拆分为三层：

```text
server/
├── tencent_docs_client.py       # HTTP/MCP 鉴权和低层请求
├── tencent_docs_space.py        # 查询/创建目录、创建或查找项目表
├── tencent_docs_repository.py   # 项目表读取、查询、去重、追加、更新
└── tencent_docs_cache.py        # 短时缓存（可选）
```

### 5.1 建议 API

| 接口 | 说明 |
| --- | --- |
| `GET /api/tencent-docs/connection` | 查看是否已连接、当前目录表 |
| `POST /api/tencent-docs/connection` | 绑定根目录和目录表 |
| `GET /api/tencent-docs/projects` | 从目录表读取项目列表 |
| `POST /api/tencent-docs/projects` | 创建或绑定项目 |
| `GET /api/tencent-docs/projects/{id}/products` | 读取、筛选、分页查询项目商品 |
| `POST /api/tencent-docs/projects/{id}/products/sync` | 去重后追加/更新商品 |
| `POST /api/tencent-docs/projects/{id}/refresh` | 清除缓存并强制读取在线数据 |

### 5.2 客户端能力要求

需根据实际腾讯文档账号和授权能力确认以下接口可用性：

- 查询空间节点/文件夹；
- 创建文件夹；
- 在指定父目录创建在线表格；
- 获取工作表列表与 `sheet_id`；
- 读取指定单元格区域或记录；
- 在指定行追加数据；
- 更新指定行。

腾讯文档 MCP 官方能力已列出空间节点、文档内容、表格批量更新和智能表格记录操作；但实际可调用工具和参数必须以接入账号返回的工具定义为准。[腾讯文档 MCP 官方说明](https://developer.cloud.tencent.com/mcp/server/11803)

## 6. 前端改造范围

新增“项目”概念，替代当前仅有的本地库入口。

### 6.1 导航

```text
商品搜索 | 当前项目：夏季女装 ▾ | 项目管理 | 腾讯在线库状态
```

### 6.2 项目管理页

- 连接腾讯文档；
- 展示目录表中的项目卡片；
- 创建项目、选择归档项目、归档项目；
- 显示每个项目的商品数量、最后同步时间、在线文档链接。

### 6.3 商品列表页

- 顶部显示当前项目；
- “归档”改为“同步到当前项目”；
- 同步结果显示新增、跳过重复、更新数量；
- “本地库”调整为“在线素材库”；
- 提供“刷新在线数据”按钮；
- 支持按项目表中的标签、备注、素材状态查询。

## 7. 权限、安全与数据边界

1. 腾讯文档授权令牌仅存放在后端 `.env` 或桌面端本地受保护配置中，绝不下发到浏览器。
2. 用户必须拥有目标文件夹和在线表格的查看、编辑权限；失去权限时接口应返回清晰提示。
3. 商品图片、视频等大文件不建议直接塞进腾讯表格。第一阶段继续保存在本地 `data/product_media/`，在线表格仅保存素材状态和可选路径/链接。
4. 项目表的列名应锁定；若用户手工增删关键字段，应用应提示映射修复而不是静默写错列。
5. 应记录同步时间和同步结果，方便排查重复、漏写和权限问题。

## 8. 分阶段实施建议

### 阶段 A：固定单表同步（最小验证）

- 用户手动配置一个 `file_id`；
- 读取商品 ID 列；
- 去重追加商品；
- 不创建文件夹、不做多项目。

**验收：** 同一商品第二次同步时被跳过，用户可在腾讯表中手工编辑后由素材台读取到更新。

### 阶段 B：目录表 + 多项目

- 实现目录表读取；
- 创建项目表并写入标准表头；
- 项目切换和按项目查询；
- 短时缓存和刷新机制。

### 阶段 C：空间文件夹自动化

- 查询或创建“素材台”根目录；
- 查询或创建项目文件夹；
- 创建表格时指定父目录；
- 处理移动、重命名和权限失效。

### 阶段 D：协作增强

- 同步状态/错误日志；
- 行更新和冲突处理；
- 素材云端存储链接；
- 跨项目统计与选品看板。

## 9. 待确认事项

在编码前需要确认：

1. 使用普通腾讯文档账号、企业版账号，还是腾讯文档 MCP 授权？
2. 当前凭证是否有读取表格和管理空间节点的权限？
3. 用户是否允许首次授权后由素材台自动创建“素材台”目录与目录表？
4. 归档重复时默认“跳过”还是“更新可变字段”？
5. 商品素材文件是否只保留本地，还是未来也需要上传到云端？
6. 一个项目表预计的字段数、最大商品数、团队成员数是多少？

---

## 10. 决策建议

先实施**阶段 A：固定单表去重同步**。它能验证最关键的三个条件：腾讯表读取权限、商品 ID 去重、追加写入。

验证成功后再进入目录表与项目分表。这样可避免在未确认腾讯文档实际 API 权限、返回格式和限流策略前，过早投入文件夹自动化和多项目 UI。
